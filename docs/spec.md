# Voice Hub — Technical Spec (living document)

> This is the canonical spec. It evolves from the original `/Notification Agent/voice_hub_project_prompt.md` — when those conflict, **this file wins**.

## 1. Mission

A distributed, low-latency voice interface that acts as a proactive "chief of staff." It delivers briefings generated by Cowork (the multi-agent hub), handles natural interruptible voice interaction, and executes real side effects — calendar writes, email sends, task updates — either directly via n8n (deterministic) or by escalating to Claude via Cowork (fuzzy).

Latency budget: **best 250–430 ms, typical 350–600 ms, max acceptable <1s** end-of-user-speech to start-of-TTS.

```
                            ▼
┌────────────────────────────────────────────────────────────────┐
│  n8n (Docker container on the 4070 box)                        │
│   Role: package bus + deterministic action executor            │
│   In:   packages from Cowork (webhook)                         │
│   Out:  HA service calls to trigger voice delivery             │
│   Also: Google Calendar / Gmail / Tasks write for det. intents │
│   Also: escalation webhook back to Cowork for fuzzy intents    │
└───────────────────────────┬────────────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────────────┐
│  Home Assistant Container (Docker, on the 4070 box)            │
│   Role: voice PIPELINE ORCHESTRATOR (thin passthrough)         │
│   Pipeline per utterance:                                      │
│    1. Wake word (on-device microWakeWord on HA Voice PE)       │
│    2. Audio → STT (Wyoming endpoint → Parakeet)                │
│    3. Text → conversation agent (OpenAI-compat → vLLM/Llama)   │
│    4. Response → TTS (Wyoming endpoint → Kokoro)               │
│    5. Audio out to originating device                          │
│   HA is NOT used for smart-home automations here — minimal.    │
└───────────────────────────┬────────────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────────────┐
│  AI layer (GPU-resident on the 4070)                           │
│   • Parakeet RNN-T (NeMo) + Wyoming wrapper  — streaming STT   │
│   • vLLM serving Llama 3.1 8B fp8            — OpenAI-compat   │
│   • Kokoro + Wyoming wrapper                 — streaming TTS   │
└───────────────────────────┬────────────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────────────┐
│  Voice endpoints (ears + speakers)                             │
│   Main room:   ReSpeaker XVF3800 → Pi 4 (2GB, AUDIO BRIDGE     │
│                ONLY, no inference) → AUX → Sony SRS-XB100      │
│   Bedroom:     HA Voice PE satellite                           │
│   Family room: HA Voice PE satellite                           │
│   Office:      HA Voice PE satellite                           │
└────────────────────────────────────────────────────────────────┘
```

**Key architectural clarification (vs original docx).** HA is not "between n8n and AI layer" — it orchestrates the STT → conversation agent → TTS pipeline on each utterance, and vLLM plugs into HA as the **conversation agent** via HA's OpenAI-compatible integration. n8n sits *after* the conversation agent returns, handling deterministic actions and escalating fuzzy ones. This makes HA a thin protocol layer, not a decision-making node.

## 4. Interaction model

```
[User speaks]
  → HA Voice PE detects wake word locally
  → Streams audio to Parakeet via Wyoming
  → Parakeet emits partial hypotheses continuously
  → Each partial goes to vLLM as the conversation agent
    → vLLM updates an evolving "intent frame" (speculative)
    → TTS stays silent until commit
  → STT commits on endpoint or ~500ms silence
  → vLLM returns structured response:
      { "speak": "...", "action": {...} } or { "escalate": {...} }
  → If "action" and deterministic: n8n executes, TTS speaks the confirmation
  → If "escalate": n8n posts package to Cowork, TTS speaks a holding reply,
     response returns via webhook for follow-up TTS
  → Barge-in: any speech during TTS cancels TTS + resets intent frame
```

## 5. Package protocol

See `package_protocol.md` for the v0 schema. Summary:

Packages carry either pre-computed content for Voice Hub to speak (briefings, alerts) or requests for Voice Hub to ask the user something (confirmations, proposed actions). Responses from the user flow back as packages of `kind: "user_response"`.

## 6. Action taxonomy

See `action_taxonomy.md`. Summary:

- **Deterministic intents**: n8n executes directly (calendar write, task complete, canned message). Sub-second, no Claude round-trip.
- **Fuzzy intents**: packaged and sent to Cowork; Claude executes via MCPs; response returned to voice. Multi-second, but the voice system can speak a holding acknowledgment ("Working on it, I'll be back in a moment") during the round-trip.

The local 8B's primary job is intent classification + argument extraction. Free-form generation is limited to short confirmations and acknowledgments.

## 7. Failure modes (v0 — expand in test_plan.md)

- vLLM unreachable → HA falls back to Claude API via n8n for conversation-agent role
- GPU busy (simracing, other workload) → queue or degrade to text-only notifications
- Network flap → HA Voice PE buffers locally; reconnect on recovery
- STT low confidence → ask for repeat, do NOT execute action

## 8. Privacy posture

- Mic is always-on *locally* but audio is only streamed post-wake-word
- All STT/LLM/TTS inference is on-premises; no cloud APIs in the hot path for deterministic intents
- Fuzzy-intent escalation to Cowork does go to Claude (API); user should understand what's leaving the house in those cases
- Logging retention policy: TBD (decide before first real-world use)
